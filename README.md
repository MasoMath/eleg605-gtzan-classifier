# Code Base Overview

This Repository is for Analysing the GTZAN dataset for music genre classification. To run this code you must match a specific file folder format:

```
+---boblsturm
|   +---index.txt
|   +---test_filtered.txt
|   +---test_stratified.txt
|   +---train_filtered.txt
|   +---train_stratified.txt
|   +---valid_filtered.txt
|   +---valid_stratified.txt
+---GTZAN
|   +---.complete   -> Generated by Kaggle Download
|   +---Data        -> Generated by Kaggle Download
|   \---Data_filtered
|       +---30s_split
|           +---test
|               +---[folders based on genres]
|           +---train
|               +---[folders based on genres]
|           \---valid
|               +---[folders based on genres]
|       \---3s_split
|           +---test
|               +---[folders based on genres]
|           +---train
|               +---[folders based on genres]
|           \---valid
|               +---[folders based on genres]
+---testing_files   -> .gitignore testing files
+---trained_models
|   +---adj_params
|   +---og_params
|   \---og_params_no_gb
```

There are 3 main files to acheive this, detailed below, as well as some additional useful files. 
- `GTZANDataProcessor.py` which is responsible for downloading the Kaggle data, generating the train/val/test splits according to Sturm, verifying the data matches the expected issues with the dataset, generating features from actual music files using `librosa`, and other useful preprocessing tools.
- `GTZANClassifier.py` is the main python class wrapper for containing all of the scikit-learn models for the analysis. This class handles the training, fitting, evaluating, saving, and loading for the models. It also includes plotting functions which probably should be moved to a separate file. For a given dataset and randomstate, it contains multiple models.
- `GTZANClassifierAnalysis.py` is a python class container for holding and analysing multiple `GTZANClassifier` objects. 

Other useful jupyter notebooks are scattered around for a specific question or analysis task. Many of these are just calling the functions from the above 3 files. The main file additional file of interest is `train_everything.py` which will attempt to train every model, across all requested configurations in parallel. This could take up to 20 GB of RAM and peg your CPU for an extented duration. Use with caution, or just train the models in sequence.

To get started (bash):
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

Then in a python script or jupyter notebook run:
```python
import GTZANDataProcessor as gdp

gdp.download_kaggle_data(output_dir="./GTZAN")
```
From here you'll need to create the `Data_filtered` folder in the `GTZAN` folder, and you also need to download the listed files for the [boblsturm folder from their repo](https://github.com/boblsturm/GTZAN). Once the required files are downloaded, you should copy (or create pointers) of the GTZAN audio files in `GTZAN/Data/genres_original/` to the folders in `GTZAN/Data_filtered/30s_split/[test/train/valid]` using a mapping determined by Sturm's splits. Once that's all in place, you can then generate GTZAN capitiable features using `gdp`. Either you can select specific audio tracks or you can run a parellel extraction on all of them with

```python
gpd.extract_gtzan_split_features(path_to_dir, chunk_dur, sr, n_jobs)
```

See below documentation for more details. After all of that you can load up models and train them either with the parallelized script, or by the following flow:

```python
from GTZANClassifier import GTZANClassifier

clf = GTZANClassifier(
    dirpath=dirpath, # "./GTZAN/Data_filtered/30s_split/"
    feature_subset=subset, # "full", "mfcc", or "spec" 
    random_state=rand_state
)

clf.load_and_prepare_data()
clf.add_baseline_models()
clf.add_models()
clf.fit_and_evaluate_models()

path = f'./trained_models/og_params/'
clf.save_models(path)

# To load models:
clf.load_models(
    pkl_filepath=path,
    data_filepath=dirpath
)
```

`GTZANClassifier` will store, save, and load, training time, models, random state, random forests `GridSearchCV` results, and the feature subset. When loading, the class will check that the saved random state matches the saved state in the name and throw an error if they differ.


# GTZANClassifier

## Overview
`GTZANClassifier` is an object-oriented pipeline designed to load, train, evaluate, and visualize machine learning models on the GTZAN music genre classification dataset. It supports traditional scikit-learn classifiers as well as PyTorch neural network wrappers, providing centralized tracking for training time, errors, training metrics, and split-specific performance evaluations.

## Features
* Automated data loading and feature subset filtering (`full`, `spectral`, or `mfcc`).
* Training and evaluation pipelines for K-Nearest Neighbors, Support Vector Machines, Random Forest, and Ensemble voting models.
* Integrated PyTorch neural network model support via `PyTorchGenreClassifier` with validation and early stopping support.
* Performance evaluation across specific dataset splits (`train`, `val`, `test`) using balanced accuracy, macro F1-score, precision, recall, confusion matrices, and per-class breakdowns.
* Persistence methods to save and load model states, evaluation metrics, and independent companion neural network weights (`_nn_weights.pt`).

## Functions and Methods

### Initialization & Helpers
* `__init__(dirpath, feature_subset, labels, random_state)`: Initializes the classifier configuration, data directories, and model tracking dictionaries.
* `_parse_dataset_type(dataset_type)`: Validates and normalizes dataset split names (`train`, `val`, or `test`).

### Data Management
* `load_and_prepare_data()`: Loads the training, validation, and test dataset splits from the specified directory.
* `_load_dfs(dirpath, data_type)`: Helper function to load and parse specific CSV split files.
* `split_data(test_size, val_size, X, y)`: *Deprecated.* Retained for legacy compatibility.

### Model Addition and Configuration
* `add_baseline_models()`: Builds and adds baseline KNN and Linear SVM pipelines.
* `add_models()`: Runs grid search parameter optimization for RBF SVM and Random Forest models.
* `add_nn_model(...)`: **[WARNING: This function implements neural network components which are new and still being tested.]** Adds a PyTorch neural network model instance to the model collection with validation support enabled.
* `_find_best_k(k_end, displayPlot)`: Determines the optimal $k$ value for KNN using validation balanced accuracy.

### Training and Evaluation
* `fit_and_evaluate_models()`: **[WARNING: This function supports neural network training paths which are new and still being tested.]** Trains un-fitted models, records training times, tracks errors, and stores training information under `model_dict['training metrics']`.
* `compute_and_store_metrics(dataset_type)`: **[WARNING: This function supports specialized split evaluations which are new and still being tested.]** Computes macro and per-class metrics for a specified dataset split, storing results under `model_dict['metrics'][dataset_type]`.
* `predict(X, target_model)`: **[WARNING: This function interfaces with neural network prediction modules which are new and still being tested.]** Generates categorical predictions using a specified model.

### Serialization
* `save_models(filepath)`: **[WARNING: This function handles neural network weight checkpoint serialization which is new and still being tested.]** Serializes model metadata via joblib and delegates independent PyTorch neural network weights to companion `.pt` files per model.
* `load_models(pkl_filepath, data_dirpath)`: **[WARNING: This function handles neural network weight checkpoint loading which is new and still being tested.]** Loads model metadata, migrates legacy flat metrics layouts for backward compatibility, and re-links distinct companion PyTorch weight files.

### Visualization and Reporting
* `print_metrics_summary(dataset_type)`: Prints a summary table of performance metrics across all trained models for a specified dataset split.
* `print_per_class_metrics(model_name, dataset_type)`: Prints classification metrics broken down by genre class for a specific model and dataset split.
* `plot_confusion_matrices(model_names, data_split, displayPlot)`: Plots a comparative grid of confusion matrices.
* `plot_metric_comparison(metric, data_split, displayPlot)`: Plots a bar chart comparing performance metrics across models.
* `plot_resource_comparison(metric, memory_unit, displayPlot)`: Plots resource utilization metrics such as training time, model memory, or file size.
* `plot_per_class_heatmap(metric_key, data_split, displayPlot)`: Creates a heatmap showing per-class scores across all models for a specified data split.

## Known Bugs and Limitations
* **Feature Column Ordering:** `_load_dfs()` and `predict()` assume feature columns match the exact column order of the original Kaggle GTZAN dataset. The location of the `tempo` column is used to split spectral and MFCC features.
* **Model Version Dependency:** Saved model files are closely bound to the class code structure. Changes to the implementation generally require retraining and regenerating saved checkpoints.
* **Filepath Precision:** `save_models()` requires directory paths to be specified precisely with a trailing slash (e.g., `./GTZAN/Data_filtered/30s_split/`).

# GTZANClassifierAnalysis

## Overview
`GTZANClassifierAnalysis` loads saved `GTZANClassifier` models across dataset variants, feature subsets, and random seeds, aggregates evaluation metrics and resource footprints into a master DataFrame, and generates comparison tables, heatmaps, scatter plots, and confusion matrix grids.

## Classes

### `GTZANClassifierAnalysis`
- **Role:** Batch evaluation, aggregation, and plotting utility for `GTZANClassifier` runs across multiple configurations and models.

## Methods and Functions

### Initialization
- `__init__(pkl_filepath, data_dirpath, sub_folder, dataset_split, feat_types, rng_states, time_states)`: Configures model checkpoint paths, dataset paths, target split (`val` or `test`), feature subsets, random seeds, time durations, and initializes the classifier registry (`self.classifers`).

### Data Loading and Aggregation
- `_create_master_df()`: Iterates over loaded classifiers and models, extracts split metrics, training time, serialized model memory, and `.pkl` file size, and builds a sorted `self.df_master` DataFrame.
- `load_data()`: Instantiates and loads `GTZANClassifier` objects for all configured `(time_states, feat_types, rng_states)` combinations and triggers `_create_master_df()`.
- `print_master_df()`: Prints the full master comparison table to stdout.
- `print_best_config()`: Prints the top-ranked configuration, model name, balanced accuracy, and macro F1 from `self.df_master`.
- `get_total_master_memory(unit)`: Sums serialized model memory in `KB` or `MB` across `self.df_master` and prints a summary report.

### Ensemble and Per-Class Comparison
- `compare_ensembles_val(baseline_model, candidate_model, split)`: Compares baseline and candidate ensemble metrics, deltas, and within-configuration ranks across all loaded configurations on the specified split.
- `summarize_ensemble_comparison(df_comp)`: Groups `df_comp` by dataset and feature subset to compute mean, standard deviation, and mean deltas across random seeds.
- `compare_per_class_val(config_name, baseline_model, candidate_model, class_names, split)`: Extracts per-genre F1, recall, support, deltas, and confusion matrices for a single configuration and split.
- `get_best_baseline_candidate_models(baseline_model, candidate_model, split, metric_keys, duration)`: Selects the highest-scoring run on the specified split for `full base`, `full cand`, `mfcc base`, and `mfcc cand`.

### Visualization
- `plot_metric_comparison(metric)`: Plots a grouped bar chart of a `self.df_master` metric across configurations and models.
- `plot_memory_footprint()`: Plots a scatter chart of serialized model memory (`KB`) against test balanced accuracy grouped by model.
- `plot_per_class_heatmap(metric_key, target_model)`: Renders a heatmap of per-class precision, recall, or F1 across genres for a target model or all models.
- `top4_configs(displayPlot)`: Selects the top 4 models across all configurations and renders a 2x2 grid of confusion matrices.
- `plot_metric_comparison_from_classifiers(metric, data_split)`: Dynamically runs `.predict()` on each loaded classifier for `data_split`, computes metrics on the fly, and plots a grouped bar chart.

# GTZAN Helper Functions

## Overview
This module provides a collection of utility and helper functions for downloading, verifying, processing, extracting features from, and visualizing audio data within the GTZAN music genre classification dataset. It utilizes `librosa`, `soundfile`, `kagglehub`, and parallel processing via `joblib` to handle audio feature extraction workflows efficiently.

## Functions

### Data Acquisition and Verification
* `download_kaggle_data(output_dir)`: Downloads the GTZAN dataset from Kaggle using `kagglehub` to a specified output directory.
* `verify_corrupt_file(data_dir)`: Recursively scans a directory for `.wav` files and attempts to load them to identify and log corrupted or unreadable audio files.
* `verify_gtzan(data_dir, s_lb, s_ub)`: Performs comprehensive structural and integrity checks on the dataset, verifying expected genre subdirectories, file counts, sample rates, channel configurations, frame count tolerance bounds, and silent or zero-padded tracks.

### Feature Extraction
* `extract_gtzan_features(mp3_path, chunk_dur, sr, label)`: Extracts a standard suite of GTZAN-compatible audio features (including spectral centroids, bandwidth, roll-off, zero-crossing rates, RMS, harmony, percussion, tempo, and MFCC statistics) broken down into time chunks.
* `extract_features_batch(mp3_paths, labels, chunk_dur, sr, n_jobs)`: Processes a list of audio files in parallel across all available CPU cores using `joblib`, filtering out corrupted loads and consolidating results into a master DataFrame.
* `extract_gtzan_split_features(path_to_dir, chunk_dur, sr, n_jobs)`: Scans a dataset split directory (`train`, `valid`, `test`), extracts features for all audio files, and exports individual split CSV datasets.

### Data Summary and Analysis
* `summarize_split_distributions(path_to_dir)`: Scans feature CSV files in a given directory and computes class label counts and percentage distributions per split.
* `get_split_summary(split_dict, metric)`: Combines train, test, and validation split dictionaries into a single consolidated summary table displaying counts or percentages per genre.

### Visualization
* `plot_spectrogram(mp3_path, sr, absolute_scale, cmap, oneFig)`: Loads an audio file and plots both a log-frequency STFT spectrogram and a Mel-spectrogram with configurable energy scaling and layouts.
* `plot_reference_style_spectrogram(mp3_path, sr, ref, top_db)`: Generates a specialized Mel-spectrogram styled to match academic literature and dataset references using the `magma` colormap and strict dynamic range bounds.

# Parallel Training Script

## Overview
This script provides concurrent execution utilities to automate the training, evaluation, and serialization of machine learning models across multiple dataset split durations and random states. It utilizes Python's `concurrent.futures.ProcessPoolExecutor` to run tasks in parallel across CPU cores using the `GTZANClassifier` pipeline.

> **WARNING:** Training everything in parallel can require up to 20 GB of RAM depending on what is being trained, without factoring in additional memory required for neural network models.

## Functions and Execution Blocks

### Functions
* `train_all_n_save_models(dirpath, rand_state, t_val)`: **[WARNING: This function implements training and evaluation routines that incorporate neural network modules, which are new and still being tested.]** Iterates through feature subsets (`full`, `spectral`, `mfcc`), instantiates a `GTZANClassifier` pipeline for each configuration, loads data, trains baseline and optimized models, computes evaluation metrics, and serializes the model artifacts to disk.

### Execution Block
* `if __name__ == '__main__':` Sets up the parameter grid across split variants and random seed states, initializes task arguments, submits jobs to a multiprocessing pool via `ProcessPoolExecutor`, and handles asynchronous completion status logging and exception reporting.
